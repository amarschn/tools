# Materials domain glossary

Status: proposed v1 vocabulary for review checkpoint 1

This glossary gives one plain-language meaning to the terms used by the M1
synthetic schema lab. It is intentionally narrower than a general materials
ontology. In v1, the product looks up numeric, source-backed property evidence;
it does not rank materials, model equations or curves, or describe complete
manufacturing histories.

The words **must**, **must not**, and **never** below describe proposed contract
rules. A JSON record is only a representation of a domain entity; “record” is
not itself another level in the material hierarchy.

## Dataset and versions

### Canonical dataset

The normalized, versioned collections from which every search, detail, and
compatibility artifact is generated. Canonical data expresses evidence and
identity, not a particular screen layout. Generated search indexes, material
bundles, and category ranges are not edited as source data.

### Contract version

The version of the allowed data shapes and semantic rules. It changes when a
producer or consumer would need different logic to understand the same data.
It is not the same as the corpus or build version.

### Corpus version

The version of the dataset contents. Adding or correcting a material or
observation changes the corpus without necessarily changing the contract.

### Generator version

The version of the code that validates canonical data and compiles delivery
artifacts.

### Build ID

A deterministic identifier derived from the contract, corpus, generator, and
generated bytes. Building identical inputs must produce the same Build ID;
wall-clock time must not affect it.

### Derived artifact

A deterministic output made from canonical data for a specific task. Examples
are a search index, a material bundle, and a property projection. A derived
artifact may be discarded and rebuilt without losing evidence.

### Synthetic fixture

An obviously fabricated dataset used to test the contract and interface. Its
IDs, sources, warnings, and output paths must make it impossible to confuse
with factual engineering guidance.

## Classification and identity

### Taxon

A named classification or browse scope, such as “engineering plastics” or
“woods.” A taxon may be empty and may overlap another classification. It never
owns observations, property values, or hand-authored material ranges.

### Primary browse parent

The one parent that places a taxon in the default browse tree. Following only
primary browse parents must produce an acyclic, deterministic path.

### Supplemental broader link

An additional useful relationship between taxa that is searchable but does not
change the default browse tree or default rollup counts.

### Material

Something a source, specification, or datasheet can identify independently: a
standard grade, commercial grade, species, pure substance, or defined composite
system. A broad chemistry or family term is normally a taxon unless a source
actually defines a generic reference material.

A material can own observations directly, have named states, or both. Direct
material observations are never silently copied to its states.

### Identity kind

A small controlled description of why something qualifies as a material, such
as `standard_grade`, `commercial_grade`, `species`, `pure_substance`, or
`composite_system`. It supports validation and display; it is not another
parent hierarchy.

### Primary taxon

The one taxon that gives a material its default browse path. Default category
rollups count the material through this path exactly once.

### Supplemental classification

An additional taxon membership that improves discovery without replacing the
primary path. For example, a filled polymer state may also be discoverable as a
fiber-reinforced polymer. Supplemental membership must not make it appear twice
in a default category projection.

### Designation

A system-qualified identifier assigned by a standard, registry, organization,
or manufacturer. “AA 6061,” for example, is not merely a synonym: the system is
part of its meaning. Designations use one canonical structured form and remain
distinct from free-text aliases.

### Alias

A phrase users may type for an entity or property. Aliases improve lookup but
do not create identity or alter taxonomy. An ambiguous alias may resolve to
several typed choices; it must not silently select one unrelated meaning.

## Materials, states, and observations

### Named state

A stable formulation or processing outcome that users or sources deliberately
name as a lookup identity under one material. Examples include T6 temper, a
30%-glass-filled formulation, or a defined laminate layup.

A state is not created merely because a test has a temperature, direction,
thickness, product form, method, or statistical basis. A state must belong to
exactly one material.

### Fixed attribute

A registered fact that defines a named state and is shared by evidence attached
to that state, such as its temper, formulation, reinforcement, or layup. Fixed
attributes are stored once on the state. They are not copied into every
observation.

### Observation

One source-traceable report about one exact property of one material or named
state. It has a stable opaque ID, a reported result, a canonical result when
numeric, basis, test and specimen context, source, and precise locator.

An observation ID must not be derived from its numeric value, because a
correction must not create an unrelated identity. Several observations of the
same property are retained when their conditions, basis, method, source, or
reported result differ.

### Observation subject

The exact thing to which an observation applies: either a material directly or
one named state. When a state is named, its parent material must agree with the
observation's material reference.

### Direct material observation

An observation whose subject is the material rather than a named state. This is
appropriate when the source identifies the material without requiring a named
state. It does not become a default for that material's states.

### Effective context

The state fixed attributes and the observation-specific conditions presented
together when evidence is displayed. Effective context is derived at read or
build time. Deriving it must not mutate the canonical observation, and a
contradictory state and observation value is a validation error.

### No implicit inheritance

The rule that an observation attached to a material is not assumed to apply to
each named state, and an observation attached to one state is not assumed to
apply to its siblings. Reuse requires an explicit, traceable observation.

## Results, uncertainty, and missingness

### Reported result

What the source actually reports. V1 distinguishes these forms rather than
forcing all of them into one point value:

- **Point:** one reported numeric value.
- **Interval:** a source-reported minimum and maximum.
- **Lower bound:** “at least” a numeric value.
- **Upper bound:** “at most” a numeric value.
- **Unavailable assertion:** the source explicitly says the property is not
  reported, not tested, or not applicable.

Only numeric result forms enter numeric projections. An interval is evidence
reported by the source; it is not an uncertainty band invented by the tool.

### Canonical result

The numeric result converted to the property's coherent canonical unit. The
original reported number and unit remain available so the conversion is
auditable.

### Uncertainty

Information about the uncertainty of a reported numeric result, such as an
explicit uncertainty interval, a standard deviation with sample count, or
implied significant figures. Uncertainty is separate from a source-reported
interval and separate from disagreement among observations.

### Absence

No evidence record exists for that property and subject. Absence means neither
zero nor “not applicable.” Only a source-backed unavailable assertion gives a
reason for missing numeric data.

### Basis

The statistical or reporting meaning of an observation, such as typical,
minimum, A-basis, B-basis, computed, or estimated. Basis belongs to the
observation and must never be inferred from a material or category.

### Condition

A registered fact about the specimen, test, or reported result that can vary
without creating another material or named state. Examples include temperature,
orientation, product form, thickness, and measured moisture content. Conditions
belong to observations. The placement decisions for v1 are recorded in
[`state-condition-matrix.md`](state-condition-matrix.md).

### Test method

The test standard or procedure used to produce an observation. It belongs to
the observation rather than the state. V1 preserves a registered method ID or a
source-reported method label; it does not attempt to model every clause and
apparatus parameter.

### Active observation

An observation included in normal records and derived projections.

### Superseded observation

An observation retained for audit history but replaced by another explicitly
linked observation. It is excluded from default numeric projections. A
superseded observation is not deleted and is not the same as a second active,
disagreeing source.

## Properties and provenance

### Property

One precisely defined measurable quantity, with a stable ID, semantic
definition, quantity kind, and canonical unit. Tensile yield strength and
ultimate tensile strength are different properties even though both have units
of pressure.

### Property group

A navigation and clarification concept containing several exact properties.
“Strength” is a property group, not an alias for one chosen strength property,
and it never has observations of its own.

### Quantity kind

The physical kind of a property's values, used to validate unit compatibility.
Properties with the same unit may still have different meanings.

### Canonical unit

The coherent unit used for validation, computation, and generated projections.
Display conversion does not change canonical data.

### Source

The identifiable document or synthetic evidence source from which an
observation came. It records title, responsible organization or publisher,
revision or date, and licensing information. Every observation, including an
explicit unavailable assertion, must reference a source.

### Locator

The precise place within a source where the result can be checked. It always has
a human-readable label and may additionally name a page, table, figure, section,
row, column, cell, or source record. A source URL without a locator is not enough
for an observation.

## Derived reference views

### Data-bearing subject

A named state with observations, or a material with direct observations. A
base material with only state-owned data is useful navigation but is not an
additional data-bearing subject.

### Eligible subject

A data-bearing subject inside the requested primary taxonomy scope, whether or
not it has evidence for the requested property.

### Covered subject

An eligible subject with at least one active numeric observation for the exact
requested property. Two observations on one subject still count as one covered
subject.

### Property projection

A generated, version-specific view of one exact property across the primary
taxonomy tree. It reports raw observed endpoints, coverage counts, and mixed
condition warnings. It is never stored on a taxon and never sorted to imply a
winner.

### Observed corpus span

The minimum and maximum reported numeric endpoints among active observations in
a projection. A source-reported interval contributes its endpoints; uncertainty
does not silently widen the span. The span describes only the covered corpus,
not a specification, design range, recommendation, or complete category.

### Condition set

One distinct combination of effective conditions, test method, and basis used
for coverage reporting. It helps reveal when a category span combines unlike
evidence.

### Mixed-condition warning

A deterministic warning that covered observations differ in a material context
that matters, such as temperature, orientation, moisture, product form,
thickness, formulation, layup, method, or basis. It is context, not a quality
score.

## Delivery terms

### Manifest

The small entry point that names versions, counts, artifact paths, hashes, and
the synthetic-data warning for one generated build.

### Search index

The eagerly loaded delivery artifact containing typed names, IDs, aliases,
designations, taxonomy scope, and compact property availability. V1 search data
contains no numeric property values, prose descriptions, source details, or
preselected “best” observations.

### Material bundle

The lazy-loaded delivery artifact needed to render one complete material
datasheet: material identity, named states, observations, and their source and
locator references.

### Property projection artifact

The lazy-loaded delivery artifact needed for one exact property reference view.
It contains generated taxonomy rows, observed spans, coverage counts, warnings,
and material/state targets, all reproducible from canonical observations.

## Explicitly deferred from v1

- property curves, equations, tensors, and time-dependent models;
- ordinal ratings such as machinability or corrosion resistance;
- raw specimen and replicate datasets beyond summarized uncertainty and sample
  count;
- full manufacturing recipes, thermal cycles, cure schedules, and process
  histories;
- batch, lot, supplier inventory, price, and time-varying availability;
- automatic equivalence between similarly named states from different sources;
- implicit observation inheritance or inferred representative category values;
  and
- comparison, ranking, selection advice, and “best material” semantics.
