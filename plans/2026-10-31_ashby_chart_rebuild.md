# Ashby Chart Rebuild From Study F

Date: 2026-10-31

Turn prototype F into the real tool at `/tools/ashby-chart/`. The prototype is approved
for how it looks and works. It is not production code, because it simplifies the data.
This plan keeps that interface and restores the data rules of the live chart.

Reference: `_internal/prototypes/2026-10-31_ashby-chart-ui/f-combined/`.

**Status:** milestones 1 to 7 are built on `task/ashby-chart-rebuild`, with the release steps
and person checks still open. Three decisions changed during the build. The release manifest
loads after the first chart, because it was the largest file on the page and only confirms the
build. A group drawn mostly from reported bounds gets no outline, and the panel names it. The
data details for tests stay in `selection.json`, which the page no longer loads.

## What ships

- Studio as the default view: full-width chart, clickable axes, log or linear scales,
  formula axes, colour and size by property, saved views, keyboard shortcuts.
- One Ashby oval per family, or per class, with smooth pebbles and points only as options.
- Click a point to tag it or add a draggable label box. Box and lasso for several
  materials, with a box that can be moved and resized.
- Selection stack as an add-on panel: typed filters, histograms, class, source, tag,
  search, drawn regions, selection lines, reordering, and funnel counts.
- Design brief inside the stack panel, with a ranked results table, CSV, and Compare.
- Parallel view that shares its filters with the chart.

3D, the matrix view, gooey blobs and density contours stay out.

## The main problem: matching values across properties

F shows one median value per material and property, and ignores test conditions. The live
chart pairs exact observations with `compatible_observations` and stores results for
each pair of properties. Pairs are not enough here, since `UTS/rho` against `E/rho` and a
parallel plot both need three or more properties to agree.

**Decision: publish one table of compatible rows.** A row is a largest possible set of
mutually compatible observations for a material, with at most one per property. Every
view reads this table and keeps the rows that have the properties it needs. Pairing logic
stays in Python, so the browser has no second copy of it.

A spike on the current catalog supports this
(`_internal/prototypes/2026-10-31_ashby-chart-ui/spike_compatible_rows.py`):

| Check | Result |
| --- | --- |
| Rows for 1,453 materials | 2,162 (1,393 materials have one row; the most is 125, for an Atlas steel) |
| Published pairs missing from the rows | 0 of 11,260 |
| Pairs in the rows that are not published | 0 |
| Build time for the rows | Under 0.1 s |
| Observations, materials and rows, gzip | About 90 KB, against 1,486 KB for `selection.json` |

The count is for a first version of the file. It leaves out search names, sources, ranges
and index data, so expect it to grow. The budget below allows for that.

## Milestones

Each milestone ends with its tests passing. All of it stays on one branch and ships as one
deploy.

### 1. Data

- Add the row table and a compact file, `data/materials/selection-core.json`, generated by
  `scripts/build_material_selection.py`. It holds what the first paint needs.
- Move citations, conditions and notes into a details file, fetched when someone opens
  Sources, exports CSV, or opens the inspector.
- Keep the check that rejects a data file from a different Materials build, on both files.
- Publish each performance index in a structured form from `pycalcs/material_indices.py`,
  so the browser can evaluate it and draw its lines. An index that is not a power law keeps
  Python-computed scores.
- Tests: the rows reproduce every published pair; every pair in a row is compatible; the
  browser's index values match `INDICES[key].compute` on every pair.

### 2. Engine

- Move the chart, shapes, formula parser, filter stages and tag store from `core.js` into
  modules under `tools/ashby-chart/`, with node tests. Use the CSS variables `DESIGN.md`
  requires, and keep family colours as the one exception since they encode data.
- Replace `envelopes.js` with the oval method. Keep its test cases where the rule still
  holds: reported bounds never define a shape, interval endpoints do, and a lone point has
  no shape.
- Remove Plotly.

### 3. Chart view with full data honesty

Everything the live chart does with values must still be there:

- One point per compatible pair, so a grade with three states shows three points.
- Open markers and inequality labels for reported bounds; range bars for intervals.
- Temperature and result type filters, defaulting to 20 to 25 °C plus unstated.
- Inspector with both citations, each observation's conditions, both temperatures, and the
  link to the Materials datasheet.
- CSV in SI with kind, basis, ranges, citations and the build ID.
- The Materials list, including grades with no value on the current axes and a suggested
  chart for them.
- Isolines and the index derivation, scope and source text.
- Theme, density and precision settings.

**New: save the chart as an image.** Plotly provides a PNG download today, so removing it
would lose this. The export must include label boxes.

### 4. Tags, labels and selection

- Port single-material tags, label boxes, the movable box, lasso and the action bar.
- Tags stay on the material. A label attaches to the material and state. When that has
  several points, it uses the one clicked until the axes change, then the first available.
- Tags and labels are saved in the browser only. Copy link carries axes, filters and
  label boxes, so a shared link looks the same. A shared link does not carry tags.

### 5. Stack, brief and results

- Port all stages. Stages test rows, using the observation each row holds for that
  property, so a limit never mixes values from incompatible conditions.
- Typed filters convert or refuse units, as F does now.
- The brief uses the published index, including yield strength for the "strong" cases.

### 6. Parallel

- Port it onto the row table, one line per distinct row on the chosen axes.
- Drawing marks for bounds and intervals on parallel axes needs a design pass. Starting
  point: a dashed line segment for any line that passes through a reported bound.

### 7. Page, links and docs

- Keep the URL, title, `h1`, meta description, analytics, and the "Reading an Ashby chart"
  section, since Ashby chart searches are the site's largest source of clicks.
- The app fills the first screen and the page scrolls to the explanation below it. The
  wheel zooms only with the pointer over the plot. On phones, keep a margin outside the
  plot so a finger can still scroll the page.
- Old shared links keep working: `x-prop`, `y-prop`, `families`, `grouping`,
  `envelope-mode`, `perf-index`, `point`, and the filter parameters.
- Move `tools/ashby-chart/prototypes/` into `_internal/`. It is public but unlinked today.
- Update the README and roadmap, and rerun the discoverability scripts.

## Decisions already made

| Topic | Decision | Why |
| --- | --- | --- |
| Isolated materials and ovals | A few may sit outside, and the panel says how many | Matches F. It replaces the live rule that an outline contains every grade, so that test changes on purpose. |
| Strong brief | Uses yield strength, as the published index does | F used tensile strength. Fewer materials qualify: 132 against 446, and no wood. Tensile strength stays available as a formula or plain axis. |
| Formula units | Display units (GPa, MPa, kg/m³), stated by the axis | Easy to type. Index scores and CSV stay SI. |
| Limits and bounds | A reported minimum is compared at its reported value and stays marked as a bound | Same screening rule as today. The stage shows how many bounds it includes. |
| Accounts or tag sync | None | Static site. Tags stay in the browser. |

## Acceptance

**Data:** every test in `tests/test_material_selection.py` still passes. For a sample of
property pairs, the chart's points match the published pairs exactly. Titanium still shows
its 20 °C and 22 °C values in the inspector and CSV.

**Speed, on a throttled "fast 4G" profile with a cold cache:**

| Measure | Budget |
| --- | --- |
| Core data, gzip | Under 200 KB |
| First chart drawn | Under 1.5 s |
| Filter or family toggle, to next frame | Under 50 ms on 1,453 materials |

**Browsers:** Chromium, WebKit and Firefox all run the browser tests. Drag tests must check
that no native text selection starts, because that was a Safari-only bug in F.

**Accessibility:** the canvas has no readable content, so the results table and Materials
list must offer the same materials and values by keyboard and screen reader. Respect
reduced motion, and keep focus visible.

**Repository gates:** `python3 -m pytest -q`, `node tests/browser/ashby-envelopes.cjs` or its
replacement, `node tests/browser/materials-explorer.cjs`, the lookup Node and browser
suites, `python3 scripts/build_site.py`, and the release verification. The explorer test
reads Plotly internals today, so its checks need rewriting against the new page. Its checks
of behaviour stay.

**Person checks, which I cannot do:** pinch zoom and label dragging on a real phone, and a
final look in real Safari.

## Risks

- **Rows can multiply.** The largest material has 125 rows today. A new batch with many
  conditions could grow this quickly, so the build should fail above a set limit per
  material, for someone to review.
- **More points than F.** Real pairs add points and F's ovals were tuned on one per
  material. Check every preset by eye after milestone 3.
- **Sparse parallel plots.** Many property combinations have few materials. The coverage
  count stays visible, and Add axis keeps choosing the property with the most data.
- **SEO.** Replacing the page could affect the site's best traffic. Keep all text and
  metadata as they are, and compare search clicks for a few weeks after release.
